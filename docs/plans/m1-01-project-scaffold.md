# Plan m1-01: Project scaffold

- Milestone: M1
- Depends on: none
- Status: done
- Branch: `feature/project-scaffold` from `main`

## Goal

A Next.js + TypeScript strict application that runs locally, with linting, type-checking, unit tests and CI on pull requests, so every following milestone starts from a verified baseline.

## Tasks

1. Create the Next.js app (App Router, TypeScript, ESLint, Tailwind CSS, `src/` directory, import alias `@/*`). `create-next-app` refuses a non-empty folder: generate it in a temporary directory and move the files into the repository root, keeping the existing `docs/`, `README.md`, `CLAUDE.md`, `.github/`, `.gitignore` and `.editorconfig` (merge `.gitignore` entries if needed).
2. Enable `strict` in `tsconfig.json` (and `noUncheckedIndexedAccess`).
3. Add Prettier with an ESLint-compatible config and `prettier-plugin-tailwindcss` (sorts class names); scripts `lint`, `format`, `type-check`.
4. Add Vitest with one sample test for a utility in `src/lib/`; script `test`.
5. Add `.env.example` (empty for now, with a header comment explaining the convention).
6. Add `.github/workflows/ci.yml`: on pull request, install with `npm ci`, run `lint`, `type-check`, `test`.
7. Replace the default home page with a minimal DocFlow placeholder (product name, one-line description). The real login page, which also presents the product, comes in M2.
8. Update `README.md` (Getting started) and the Commands section of `CLAUDE.md`.

## Verification

- `npm run dev` shows the placeholder page at `http://localhost:3000`, styled with Tailwind classes (for example a centred title with `text-3xl font-semibold`).
- `npm run lint`, `npm run type-check`, `npm test` pass locally.
- The pull request shows the CI check green.

## Out of scope

Supabase, authentication, any AI integration.

## Outcome

All eight tasks done. Deviations from the plan:

- **`AGENTS.md`** generated by Next.js 16 (points coding agents to the docs bundled in `node_modules/next`) is kept and committed.
- **`@types/node` upgraded from 20 to 24.** Vitest 5 requires `@types/node` 22 or newer; 24 matches the Node.js version used locally and in CI.
- **`vitest.config.mts`** instead of `.ts`: the project is CommonJS and Vite warns about ESM syntax in a `.ts` config.
- **Prettier ignores `*.md` and `docs/`** so that tables in the documentation are not reflowed. An extra `format:check` script verifies formatting without writing.
- **VS Code settings** (`.vscode/settings.json`, `extensions.json`): format on save with Prettier, ESLint fixes on save.
- **Pre-commit hook** (Husky + lint-staged): lints and formats staged files and runs `type-check`. Tests are left to CI to keep commits fast.
- **`type-check` runs `next typegen` first.** The first CI run failed with `TS2304: Cannot find name 'LayoutProps'`: Next.js generates those global types on `dev`/`build`, so they were missing on a clean checkout. Fixed in a follow-up PR; the PR of this plan had been merged with a red check.
- The home page copy is in Italian and the document language is `it`, since the product targets Italian users.
